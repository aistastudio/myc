# memory-501fa4jp7xpw — цена кеша в ростере

## Корень

Формула стоимости (`packages/swarm/src/attribution.ts` `#freezeCost`) **всегда**
считала все четыре ставки. Ноль приходил из ввода: у `myc model add/update`
не было флагов для ставок кеша, а `Roster.#insertPrice` подставлял
`price.usdPerMCacheRead ?? 0`. Второго пути ввода цены в репозитории нет —
`addModel` вызывается только из `packages/cli/src/commands/roster.ts` (и из
тестов); проверено grep'ом по `packages/`.

## Что сделано

**Ввод — тот же путь, четыре ставки вместо двух.**
`myc model add|update … --price-cache-read X --price-cache-write Y` пишут в ту
же строку `swarm_model_price`, тем же `#insertPrice`, с той же датой.

**Умолчание — явное и названо в выводе.** Ставок не задали — применяются доли
`CACHE_PRICE_SHARES = { read: 0.1, write: 1.25 }` от `--price-in`, и команда
говорит вслух:

    WARN price.cache_defaulted: ставки кеша не заданы: применено умолчание
    read=10%, write=125% от --price-in 3 → read 0.3, write 3.75 $/1M.
    Это допущение, а не прайс провайдера: задайте --price-cache-read/--price-cache-write

Доли живут только в слое ввода: в базу ложатся вычисленные **числа**, счёт
стоимости о долях не знает. Ноль после этого можно завести лишь явным
`--price-cache-read 0`.

**Ноль перестал быть тихим.** `RosterEntry.cacheUnpriced` (обе ставки нулевые)
виден в `model list/show` — в JSON и в человеческой таблице. `model show`
печатает в истории все четыре ставки, а не две (раньше кеш из истории просто
не было видно — потому баг и жил).

**Точная дата.** `--price-date` принимает и полный ISO
(`2026-09-05T16:14:11.794Z`), не только `YYYY-MM-DD`. Нужно, чтобы **исправить**
уже записанный факт цены (ключ таблицы — `model_id+valid_from`), а не завести
рядом второй: неполно введённая цена — ошибка ввода, а не новая цена с новой даты.

**Отчёт называет испорченный счёт.** `compareModels` считает две новые величины
в `coverage` (цену открывает только для этого, стоимость по-прежнему берётся
замороженной):
- `costCacheUnpriced` — попытки, замороженные по нулевой цене кеша при
  ненулевых кеш-токенах;
- `costStale` — замороженное число, которого его же строка цены больше не даёт
  (цену исправили после заморозки).

`myc report models` печатает по строке ВНИМАНИЕ на каждую, с командой починки.

**Пересчёт заморозки — разовый скрипт, не поведение.**
`scripts/recost-attempts.ts` пересчитывает `cost_usd` по **той же** строке цены
(`price_valid_from`), только для `cost_basis='priced'` с ненулевым кешем; по
умолчанию сухой прогон, пишет `--apply`. Инвариант «стоимость заморожена» в
коде не тронут: это исправление ошибки ввода, а не пересчёт по новой цене.

## Тест приёмки и мутации

Тест `перестановка: с ценой кеша дешевле оказывается ДРУГАЯ рука`
(`packages/swarm/src/cache-price.test.ts`) сравнивает **две руки с разной долей
кеша** при **одном прайсе**: `p/reader` (out 20k, кеш-чтений 20M) и `p/writer`
(out 120k, кеш-чтений 1M). По выходным токенам дешевле reader ($0.30 против
$1.80), по полному счёту — writer ($6.68 против $2.48). Ответ переставляется.
Рядом лежит тест `равная доля кеша: ответ не переставляется` — он показывает,
почему проверка на равномерное занижение не годится: при одинаковом профиле
обеих рук ответ не меняется и на сломанной формуле.

| мутация | что ломает | падает |

| M1 `#freezeCost`: слагаемые кеша × 0 | формулу счёта | `перестановка`, `costStale`, `--from-transcript` (3) |

## Живая проверка: настоящий ростер, настоящие попытки

Пять активных моделей ростера имели `usdPerMCacheRead=0`, `usdPerMCacheWrite=0`.
Ставки заведены `myc model update <id> --price-date <точный ISO> --price-cache-read …
--price-cache-write …` — существующие строки цен **исправлены**, новых не
появилось (`model show sonnet` → `priceHistory` длиной 1). У всех пяти
`cacheUnpriced: false`.

## Что осталось

1. **Ставки для не-Anthropic моделей — допущение.** `glm-flash` (0.06/0.75) и
   `kimi-k3` (0.1/1.25) заведены по тем же долям 10%/125%, потому что фактов их
   прайса у нас нет. У `claude-*` доли совпадают с прайсом Anthropic. Заменить
   фактами: `myc model update <id> --price-cache-read … --price-cache-write …`.
2. **Модель `проба`** (disabled, попыток 0) осталась с нулевыми ставками —
   не трогал.
3. **Сами доли умолчания** живут в `CACHE_PRICE_SHARES` в CLI. Если координатор
   решит, что даже такое умолчание нежелательно, снять его — одна правка
   `cachePrice`: вернуть `usage.price` вместо доли.
4. **docs/design/04** формулу описывает верно (все четыре ставки) — правок не
   требовала; каталог вне границ задачи, не трогал.
