## Итог

`head_id IS NULL` больше не встречается в исходниках нигде, кроме `historyClause`
(`packages/core/src/graph.ts:1039`), одного явного долга за границей задачи и
определения частичного индекса в неизменяемой миграции. Копии `headOf`/`chain_of`

По дороге найден и починен **настоящий дефект**, а не только дублирование: см. §5.

## 3. Миграция — не копия, и это важно

`packages/store-sqlite/src/migrations/001-init.ts:120` менять **не нужно и нельзя**, но
не потому, что «миграции неизменяемы», а по существу:

```sql
CREATE INDEX ix_nodes_prime ON nodes(scope, layer, salience DESC)
 WHERE layer >= 2 AND head_id IS NULL AND deleted_at IS NULL;
```

Это не запрос, а **схемная половина того же инварианта**. SQLite использует частичный
индекс, только если WHERE запроса влечёт WHERE индекса, поэтому `prime_digest_scan`
с `INDEXED BY ix_nodes_prime` обязан спрашивать ровно то, что индекс обещает. Свести
её к `historyClause` невозможно в принципе: для `full_history` функция вернёт пустоту,
а у объекта схемы режима чтения нет. **Следствие для §6.3:** `include_superseded`
на поверхности `prime` потребует не только снять предикат, но и снять `INDEXED BY` —
иначе SQLite откажется от плана. Это отдельная работа, я её не делал.

План запроса после правки проверен, он не изменился:

```
BEFORE: SEARCH nodes USING INDEX ix_nodes_prime (scope=? AND layer>?)
AFTER : SEARCH nodes USING INDEX ix_nodes_prime (scope=? AND layer>?)
```

## 4. Сторож — `packages/core/src/history-predicate.test.ts`

Устроен по образцу «CREATE TABLE вне набора миграций не появляется»
(`schema.test.ts`): обход файлов, срезание комментариев, точный список исключений.
Отличия от образца, сделанные намеренно:

* обходит **и `packages/`, и `scripts/`** — три копии жили именно в `scripts/`;
* список законных мест **точный** (`toEqual`, не «разрешено хотя бы это»): краснеет
  и на новой копии, и на протухшем исключении;
* отдельный тест утверждает, что предикат в наборе миграций — ровно один и ровно
  внутри `CREATE INDEX ix_nodes_prime`;
* отдельный тест закрывает вторую половину болезни: `head_id = ?` (чтение строк
  цепочки) встречается только в ядре.

**Осознанная дыра:** `*.test.ts` пропускаются. Тест, проверяющий, что возвращает
`historyClause`, обязан написать строку буквально — иначе он не проверяет ничего.
Тот же компромисс в сторо́же `CREATE TABLE`. Копия, заведённая в тесте, сторожем
не ловится.

## 5. Найденный дефект: сборка цепочки зависела от того, откуда спросили

Пункт 3 задачи потребовал общей сборки цепочки, и первая версия `collectVersions`
повторяла приём, который был в `show.ts`: один проход обхода по снимку уже найденных
строк. На этом многопроцессный тест слияния (`show.test.ts`, «две машины надстроили
свою версию над общим предком», настоящие `Bun.spawn`) стал падать **2 раза из 25**:

```
// 5. Режим follow из любого звена даёт ту же голову.
expect((await showJson<ShowView>(A, id)).head?.id ?? id).toBe(headA);
Expected: "myc-75v01vdsd5ct"
Received: "myc-jv0yd7r1dtqg"
```

Причина: если раскрывать связи только у звеньев, найденных от стартового узла,
собранное множество версий — а с ним и выбранная голова — зависит от того, из какого
звена спросили. Это ровно то расхождение, которое §6.3 запрещает.

Починка — **замыкание вместо одного прохода**: раскрывается каждое найденное звено
(вверх по `head_id`, вниз по указателям, по рёбрам `supersedes` в обе стороны) до
исчерпания или бюджета чтения.

Изоляция причины (одиночный тест, 25 прогонов на конфигурацию):

| реализация | падений |
|---|---|
| исходная (`show.ts`, один проход, снимок) | 0 / 25 |
| моя первая (один проход, другой набор сидов) | **2 / 25** |
| замыкание (сдано) | **0 / 50** |

Исходная реализация на этом стенде не мигала, но подвержена тому же классу: её набор
тоже зависит от стартового звена, просто окно снимка другое. Замыкание закрывает класс,
а не конкретный прогон. Записано в память: `memory-zy9ba228m5qv`.

## 6. Мутации

### Мутация 1 — вернуть копию предиката в `fts.ts`
Сторож покраснел, назвав файл:
```
error: expect(received).toEqual(expected)
    "packages/core/src/graph.ts",
+   "packages/retrieval/src/fts.ts",
(fail) `head_id IS NULL` в исходниках — только в historyClause и в списке исключений
 2 pass  1 fail
```

### Мутация 2 — `historyClause` всегда возвращает фильтр (полная история беднеет)
```
(fail) режимы истории (§6.3) > предикат head_id IS NULL живёт в одном месте, а не в восьми запросах
 29 pass  1 fail
```
Ловит `packages/core/src/history.test.ts:87` (`historyClause("full_history")` обязан
быть пустым). Проверено, что это ловится **детерминированно**: 5 прогонов из 5.
Отмечу честно: поведенческого теста, который бы падал на этой мутации через
поверхность (`show --chain`, `recall --history`), сейчас нет — потому что ни одна
поверхность полную историю ещё не отдаёт. Он появится вместе с `--history`.

### Мутация 3 — убрать законные исключения и срезание комментариев
Сторож начинает **врать**: обвиняет единственный законный дом предиката и путает
прозу с кодом.
```
    "packages/cli/src/commands/bootstrap.ts",
+   "packages/cli/src/commands/prime.ts",       ← комментарий, не SQL
+   "packages/cli/src/commands/show.ts",        ← комментарий, не SQL
+   "packages/core/src/graph.ts",               ← сам historyClause
+   "packages/retrieval/src/fts.ts",            ← комментарий, не SQL
+   "scripts/reindex-vectors.ts",               ← комментарий, не SQL
 1 pass  2 fail
```
Второй тест при этом обвиняет `absorb.ts` в копии запроса цепочки, которой там нет:
осталось только упоминание в комментарии.

## 9. Что осталось нерешённым

1. **`bootstrap.ts:725`** — последняя живая копия предиката, за границей задачи.
2. **`include_superseded` / `myc show --history` не реализованы.** Задача сняла
   препятствие (предикат в одном месте), но саму ручку не заводила — этого в задании
   не было. Кто возьмётся: для `prime` придётся снять `INDEXED BY ix_nodes_prime`
   вместе с предикатом (§3), для `hybrid`/`fts`/`vector` достаточно протащить
   `HistoryMode` в параметры запроса — но `defineQueries` требует статического SQL,
   значит на каждый запрос нужен второй вариант либо построение SQL по режиму.
3. **Поведенческого теста на мутацию 2 через поверхность нет** (§6) — появится вместе
   с `--history`.
4. **`*.test.ts` вне сторожа** (§4) — осознанная дыра, унаследованная от образца.
