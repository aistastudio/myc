# myc-rjm — хук PreCompact

Решение D11: сжатие контекста — единственный момент, когда контекст теряется
гарантированно. Хук встал, сработал на этом репозитории, числа ниже — замеренные,
не расчётные.

## Приёмка: числа

**Порядок записи.** Транскрипт → маскирование секретов → **сырой эпизод** →
кандидаты → очередь `distill` → спасательный пакет → уборка. Разбор транскрипта
идёт ПОСЛЕ эпизода: шапка эпизода содержит только то, что известно бесплатно.

**Сырой эпизод, бюджет 6 мс** (замер на реальных транскриптах Claude Code):

| Транскрипт | Эпизод | Весь хук |
|---|---|---|
| 119 КБ | **1.35–2.54 мс** | 14 мс |
| 659 КБ | 2.42 мс | 37 мс |
| 2.2 МБ | 4.07 мс | 99 мс |
| 3.6 МБ | 5.33 мс | 141 мс |
| 14.2 МБ | 16.44 мс → `WARN degraded.budget` | 622 мс |

Бюджет держится до ~3.6 МБ; выше — громкая деградация, а не молчание (И2).
Сжатие zstd-1: 14.2 МБ → 2.0 МБ.

**Ни одно решение не потеряно.** Каждое решение из транскрипта пишется
кандидатом `note` L2 `state=pending_review`, `salience=0`, `acl=private`, ребро
`derived_from` на эпизод, и попадает в пакет. Повторное сжатие не дублирует и не
теряет: столкновение по `content_hash` считается «уже в графе»
(`candidates_known`), а не ошибкой.

**Таймаут 8000 мс.** `--timeout 0` (искусственно исчерпанный бюджет): эпизод всё
равно записан, пакет отдан, код выхода 0, `WARN degraded.timeout`. Пропускаются
шаги, а не отменяется запись.

**Убийство процесса.** `kill-safety.test.ts` бьёт SIGKILL'ом в 20 точек жизни
хука, задержки считаются от замеренной длительности полного прогона. Первый
прогон теста показал, что окно между `rename` файла и вставкой строки узла
ДОСТИЖИМО: остаётся файл без строки. Гарантия усилена — такой файл теперь
усыновляется следующим запуском: шапка читается из самого файла, строка
восстанавливается с пометкой `attrs.adopted=true`. Инварианты:
строка узла никогда не врёт (файл к ней всегда на диске), уже записанные эпизоды
переживают все убийства, нечитаемый файл не удаляется.

**Секреты (D23).** `redactSecrets` вызывается до записи, без флага отключения.
Синтетический ключ `sk-ant-api03-…`: в файле эпизода 0 вхождений, `<redacted:…>`
на месте, в базе и в пакете — 0. На живом транскрипте 14.2 МБ замаскировано 153
секрета. Каталог `.myc/episodes/` получает собственный `.gitignore` с `*` —
приватные транскрипты лежат рядом с git и в историю попасть не должны.

**`myc wire` идемпотентен, чужого не трогает.** Повторный прогон: `changed=0`,
все пять конфигов байт в байт. Чужой хук на том же событии — конфликт, код
выхода 4, не записано ни одного файла, пока `--hook-mode` не скажет что делать.
`--hook-mode append` сохраняет чужой хук и чужой `statusLine`. `CLAUDE.md` не
трогается никогда, `AGENTS.md` — только блок между маркерами и только с
`--agents-md`. Нечитаемый JSON — конфликт, а не перезапись. `myc unwire` снимает
ровно поставленное по журналу `.myc/wire.json` и не трогает файл, изменённый
после нас.

**Хук стоит на этом репозитории.** `myc wire --agents claude --hook-mode append`:

- чужие хуки (graft, bd) сохранены все до одного, `statusLine` и
  `subagentStatusLine` не тронуты, `permissions.allow` дополнен, не заменён;
- `.claude/settings.json.myc.bak` и `.mcp.json.myc.bak` созданы;
- хук вызван так, как его вызывает Claude Code (payload на stdin), на настоящем
  транскрипте: `.myc/hooks.json` → `claude:pre-compact: count 3`, эпизоды
  записаны, `SessionStart` тоже отрабатывает (`myc prime`).

**Гейты.** `bun test` 1094 pass / 0 fail (1110 тестов, 80 файлов),
`bun run typecheck` 12/12 пакетов, `bun run scripts/deps-check.ts` passed.

## Что нашли живые данные

Два дефекта качества, которых синтетика не показала, — оба исправлены и закрыты
тестами:

1. `\b` в JS считает словом только ASCII, поэтому «Решили:» границей не является
   и **ни одно русское решение не находилось**. Границы переписаны на `\p{L}`.
2. Документация проекта, приезжающая в транскрипт как `tool_result`, попадала в
   РЕШЕНО: «Берём: ready-очередь» из `docs/design` становилось решением сессии.
   Ход теперь несёт отдельное поле `prose` — только собственная речь модели и
   человека; вывод инструментов на решения не сканируется. Вызовы `myc` ищутся
   только в командном контексте, поэтому таблица команд из §3 больше не выдаёт
   себя за вызовы.

## Открыто (заведены беды)

- `myc close-session` и `myc anchor touch` — хуки `stop` и `post-edit`
  пропускаются с `WARN degraded.hook_missing`; `HOOK_SPECS` их уже описывает,
  повторный `wire` подхватит.
- `myc doctor --hooks` — счётчики пишутся, читателя нет.
- Кандидаты `pending_review` не исключаются из выдачи ретривала (§6.2 требует).
- `redactSecrets` — 518 мс из 560 на 14 МБ (92% времени хука).

## Известные ограничения

- JSON-конфиги мержатся через `parse`/`stringify`: порядок ключей и отступ
  сохраняются, однострочные объекты разворачиваются. `wire` предупреждает об
  этом отдельной строкой и кладёт `.bak`.
- `myc` не установлен в PATH, поэтому запись `mcpServers.myc` в `.mcp.json`
  этого репозитория работать не будет, пока бинарь не окажется на PATH
  (`dist/myc` собран). Хуки работают: helper ищет `dist/myc` сам.
  `myc unwire` снимает всё.
