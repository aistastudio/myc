## 1. Громкость: op_id — идентичность, а не ключ дедупликации

`unionOplogText` (export.ts) при совпадении op_id сравнивает **содержимое**:

* быстрый путь — побайтовое равенство. Это подавляющее большинство сравнений:
  обе стороны несут общую историю, и повтор там нормален;
* байты разошлись — сравнивается **канонический вид записи**
  `rowToLine(lineToRow(·))`. Иначе другой порядок ключей или более старый
  формат строки давали бы ложный конфликт на честном обмене;
* всё ещё разное — `OplogCollisionError` с op_id и **обеими** строками.

Дальше расходятся два вызывающих, и это ровно то, что просила задача разобрать
(`graft callers unionOplogText --depth all`: `exportGraph` export.ts:598 и
`mergeOplogText` merge-driver.ts:34).

**Драйвер слияния** возвращает ненулевой код с `reason: "collision"`, называет
op_id и файл, показывает обе строки и НЕ переписывает `%A`. CLI отдаёт
`conflict.op_id` / exit 4 с подсказкой про S65. Обе версии файла остаются целы
в индексе (`:2:` и `:3:`), и сообщение прямо предлагает эти команды.

**Экспорт ведёт себя так же, и обоснование в комментарии на месте**
(export.ts, в `exportGraph`): увидев в файле каталога чужую операцию под своим
op_id, он падает **целиком и до записи хотя бы одного файла** —
`writeGraphFiles` к этому моменту ещё не вызывался, каталог остаётся байт в
байт прежним. Записать нельзя ни в одну сторону: победившая строка вытеснит
чужую операцию, а `myc import` с `ON CONFLICT DO NOTHING` потерю от повтора
уже не отличит. Тихий экспорт был бы той же потерей, что и тихий мерж (И2).

## 2. Корень: `site_id` принадлежит физическому экземпляру базы

`packages/store-sqlite/src/site-identity.ts` — `decideSiteId`: рядом с
`site_id` в `myc_meta` хранится `site_instance` = `{host, dev, ino, path}`;
при открытии экземпляр сверяется, при расхождении `site_id` перевыпускается,
прежний уходит в `site_id_prev`. Решение оформлено как **S65** в
`docs/design/ARCHITECTURE.md` — там же разбор про уже записанные операции и
про HLC.

**Правило равенства выведено замером, а не рассуждением** (Darwin 25.6 /
APFS, arm64, `stat -f "%d:%i"`):

| операция | инод | что из этого следует |
|---|---|---|
| `cp -R`, `cp -a`, `rsync -a`, `cp -c` (APFS clone), `tar x` | **новый** | копия обнаруживается всеми путями |
| `cp` поверх СУЩЕСТВУЮЩЕГО файла | тот же | восстановление бэкапа поверх базы ложного перевыпуска не даёт |
| `rsync` поверх существующего, без `--inplace` | **новый** | единственный измеренный ложный перевыпуск |
| `rsync --inplace` поверх существующего | тот же | |
| `mv` в пределах ФС | тот же, **путь другой** | путь НЕ входит в равенство |
| `ln` (жёсткая ссылка) | тот же | второй путь к тому же файлу — тот же экземпляр |
| 2000 вставок + `VACUUM` + `wal_checkpoint(TRUNCATE)` + close | тот же | жизненный цикл sqlite ложного перевыпуска не даёт |
| `stat` по симлинку | инод **ссылки** | нужен `realpath` + `stat`, не `lstat` |

Отсюда `sameInstance`: `host` обязателен, `ino` обязателен, `dev` **или**
`path` — один из двух (смена `dev` без смены пути — перемонтирование или
перезагрузка, а не копия). Стоимость проверки — один `statSync`, **0.59 мкс**
(n = 20000).

**Linux не замерян**, и это не оценка, а факт окружения: нет ни docker, ни
podman, ни colima, ни lima. Направление, на котором держится обнаружение
(копия ⇒ новый инод), там следует из конструкции — `cp` и `rsync` создают файл
через `open(O_CREAT)`, инод сохраняют только `link(2)` и `rename(2)`.
Не проверены overlayfs и сетевые ФС; там ошибка уйдёт в безопасную сторону
(лишний перевыпуск), но это надо будет измерить, а не предположить.

Ошибка настроена несимметрично сознательно: лишний перевыпуск стоит одного
нового `site_id` и одного каталога в оплоге и ничего не теряет; пропущенная
копия стоит операций. Поэтому расхождение `host` решающее — у двух Mac с
настройками по умолчанию номер загрузочного тома совпадает, и без `host`
копия на вторую машину могла бы пройти незамеченной. Цена: переименование
машины даёт один лишний перевыпуск (имя хоста нормализуется — обрезается
`.local`/`.lan`, — а на Linux вместо него берётся `/etc/machine-id`).

**База без записанного экземпляра усыновляется, а не перевыпускается.** До S65
такой записи не существовало; перевыпуск наугад раздробил бы `site_id` разом
у всех существующих воркспейсов, включая нескопированные. Копии, сделанные до
перехода, ловит часть 1 — по op_id их видно.

## Живые прогоны (что именно показал каждый)

**1. Сценарий копии, настоящий CLI.** `git init` + `myc init` + 5 задач +
export + commit; `cp -R proj copyA`, `cp -R proj copyB`; по 3 задачи в каждой,
export, commit; драйвер прописан в `merge.myc-oplog.driver`; `git merge`:

```
myc: conflict.op_id: myc merge-driver: .myc/graph/oplog/local-proj-10zilkj/00000.jsonl —
  КОЛЛИЗИЯ op_id local-proj-10zilkj:46: ...
  наша:  {"op_id":"local-proj-10zilkj:46",...,"entity_id":"proj-czehqpma4gyd",...}
  их:    {"op_id":"local-proj-10zilkj:46",...,"entity_id":"proj-dvyweqxq8b1r",...}
CONFLICT (content): Merge conflict in .myc/graph/oplog/local-proj-10zilkj/00000.jsonl
КОД ВЫХОДА merge: 1
```

Незамерженным остался ровно файл оплога. `:2:` — 72 строки, 3 вхождения
«copyA узел»; `:3:` — 72 строки, 3 вхождения «copyB узел»; рабочий файл
побайтово равен `:2:`, то есть драйвер `%A` не трогал. Ни одна операция не
исчезла. Раньше здесь было «объединение по op_id, +0 строк» и код 0.

**2. Экспорт при той же коллизии.** База copyB, каталог графа из copyA:
`КОД ВЫХОДА export: 1`, сообщение называет `op_id local-proj-10zilkj:46` и
`oplog/local-proj-10zilkj/00000.jsonl`, `diff -r` каталога до и после — без
различий.

**3. Два честных `git clone`, 5 + 200 + 200.** `origin.git`, seed с 5 узлами,
два клона (site_id `local-seed-cw5itf` и `local-seed-12k4ucn`), по 200 задач
в каждом, export, commit, merge:

```
Merge made by the 'ort' strategy.  КОД ВЫХОДА merge: 0
незамерженные: ''
myc import: файлов 5, строк 3645, новых 1800, применено 1800, повторов 0
УЗЛОВ В БАЗЕ: 405
```

Ровно 405 = 5 + 200 + 200. Этот путь не тронут.

**4. Перевыпуск закрывает сценарий копии** (тест
`oplog-collision.test.ts`, «копия с перевыпущенным site_id»): тот же `cp -R`,
но каждая копия получает свой `site_id` через `decideSiteId` — `git merge`
даёт код 0, незамерженных нет, файл общего префикса под ПРЕЖНИМ `site_id`
побайтово одинаков в обеих копиях (перевыпуск истории не переписывает),
`import` даёт 11 узлов = 5 + 3 + 3.

## Мутации

| мутант | результат |
|---|---|
| M1: `if (prev !== undefined) continue;` — назад к дедупликации без сравнения | **10 падений** из 18 |
| M2: сравнение ослаблено до `lineToRow(prev.line).op_id !== row.op_id` | **10 падений** из 18 |
| M3: сравнение ужесточено до побайтового, без канонизации | **1 падение** (ложный конфликт на другом порядке ключей) |
| M4: драйвер возвращает код 0 при коллизии | **3 падения** |

M1 и M2 — те, что названы в приёмке. M3 и M4 добавлены, чтобы тесты держали
границу с двух сторон: слишком строгое сравнение ломает честный обмен, а
код 0 возвращает исходный баг.

## За границами задачи — не правил, свожу сюда

1. **Подключение перевыпуска `site_id`.** `decideSiteId` не вызывается ниоткуда.
   Подключать нужно в четырёх местах, каждое читает `myc_meta.site_id` и при
   отсутствии минтит новый — туда же и встаёт проверка:
   * `packages/cli/src/commands/store.ts:586` (`openWorkspaceAt`),
   * `packages/cli/src/drain.ts:268` (`openDrainHandle`),
   * `packages/mcp/src/store.ts:307` (`openMcpStore`),
   * `packages/cli/src/commands/init.ts:326` (`createWorkspaceDb` — минт первого).

   Форма вызова: прочитать `site_id`, `site_instance`, `site_id_prev`, позвать
   `decideSiteId({stored, storedInstance, storedPredecessors, observed:
   observeInstance(dbPath), mint})`, записать то, что вернулось (`instance`,
   `predecessors` и, если `origin === "reissued"`, новый `site_id` + WARN
   человеку). При `origin === "reissued"` `myc_meta.last_seq` должен стать 0.
2. **`packages/store-sqlite/src/index.ts`** — барреля я не трогал. Туда стоит
   добавить `OplogCollisionError`, `MergeRefusal` и экспорт `site-identity.ts`.
3. **`packages/cli/src/commands/export.ts`** — там нет `try/catch` вокруг
   `exportGraph`, поэтому коллизия приходит человеку как `internal.unexpected`
   / exit 1 от общего обработчика `run()`. Код выхода ненулевой и сообщение
   правильное (проверено живьём), но код ошибки стоит смапить на
   `conflict.op_id` / `ExitCode.CONFLICT` — это три строки в `handler`.
4. **`docs/design/01-core-data-model.md`** — раздел про `site_id` теперь
   неполон: там `site_id` описан как свойство воркспейса, а по S65 он свойство
   физического экземпляра. Файл сейчас правит кто-то ещё (числится изменённым).
5. `packages/store-sqlite/src/site-identity.ts` — новый файл исходника в
   store-sqlite; в списке «можно» были только `export.ts`, `merge-driver.ts` и
   тесты. Сделал, потому что без него часть 2 осталась бы одним документом;
   файл новый, ни с чьей правкой не пересекается — при желании переносится
   целиком.
