# `myc link` — вход в терминале к тем же рёбрам, что и `myc_link` (memory-55ggwfrm68gp)

## Решение

**Команда заведена, а не инструкция вычеркнута.** SKILL.md, который `myc wire` кладёт каждому
агенту, велел писать ``myc link A supersedes B --reason "..."`` — и это правильная инструкция:
противоречие в памяти обязано разрешаться связью, а не затиранием. Не было входа, а не смысла.
Связывание уже умело делаться по MCP (`myc_link`), то есть агент по MCP связывал узлы, а тот же
агент в терминале и любой человек — нет. Заведён вход; текст SKILL.md **не менялся** — он был
верен полтора месяца, неверен был реестр команд.

**`myc route` НЕ заводилась.** Роутинг — это M5 (`docs/design/04-swarm-learning-and-routing.md`:
телеметрия попыток, приоры `swarm_arm`, бета-сэмплирование). Команда-заглушка была бы обещанием
второго рода. Исправлен текст: help `myc prime` больше не называет `myc route` командой этой
сборки, а говорит, что роутинг вызывается отдельно и едет с M5. Факт («prime не дублирует
роутинг») сохранён, обещание убрано.

## Что сделано

**1. `packages/cli/src/commands/link.ts`** (+ строка в `register.ts`).
`myc link <from> <type> <to> [--reason ...] [--remove]`, 9 типов — те же, что в схеме `myc_link`.

- `blocks`/`blocked-by` **не переписаны**: команда зовёт обработчик `myc dep add`/`dep rm`
  напрямую (позиционная грамматика у них совпадает), MCP зовёт его же подпроцессом. Третьей
  реализации зависимостей нет, поэтому циклы и ready-очередь ведут себя буквально одинаково.
- Остальные 7 типов идут прямым стором с той же таблицей `тип → EdgeKind`, тем же требованием
  `reason` для `supersedes`/`duplicates`, теми же кодами (`conflict.edge_exists`,
  `notfound.edge`) и тем же следом `superseded_by` на старом узле.
- Таблица типов скопирована из `packages/mcp/src/store.ts`, а не импортирована: тянуть `@myc/mcp`
  в команду — значит грузить сервер и диспетчер ради одного ребра, а реестр специально ленивый
  (`register.ts`, 2.85 мс холодного старта на графе команд). Копия не «под честное слово»:
  расхождение ловится тестом (см. мутации 3 и 4).

**2. `packages/cli/src/commands/link.parity.test.ts`** — сверка двух поверхностей одним сценарием,
как это сделано для комментариев и для путей открытия базы (`store.parity.test.ts`).
34 шага (7 типов × {создать, повтор, снять, снять снова} + blocks/blocked-by × {создать, снять} +
неизвестный тип + supersedes без reason), **68 прогонов**: те же шаги через `run()` CLI и через
`createDispatcher` MCP, в **одной базе** на двух парах узлов, ID нормализуются в SRC/DST.
Сверяются три вещи: ответ (код и сообщение), `effects`, и **строки `edges` в базе** — то есть
реальный `EdgeKind`, а не объявление о нём. Отдельно сверяется список типов команды с `enum`
в схеме тула `myc_link`.

**3. `packages/cli/src/commands/link.test.ts`** — 12 тестов на то, чего у MCP нет: грамматика argv,
коды выхода, человеческий вывод, разрешение префикса. Первый тест дословно повторяет строку из
SKILL.md.

**4. `KNOWN_MISSING` в `advised-commands.test.ts` пуст.** Обе строки закрыты, не отложены.
Список исключений, который перестал срабатывать, тест требует убирать — убран.

## Оба прогона на одном сценарии

Живьём, один воркспейс, две пары узлов, обе поверхности из исходников
(`bun run packages/cli/src/main.ts`).

**Терминал** — строка ровно из SKILL.md:

```
$ myc link live-gc70d5yx2qw8 supersedes live-cby3mvnke0dt \
    --reason "перекалибровано на 68 парах, bench/absorb-calibration.json"
live-gc70d5yx2qw8 supersedes live-cby3mvnke0dt
effects   live-cby3mvnke0dt помечен superseded_by live-gc70d5yx2qw8; старый узел сохранён · reason: перекалибровано на 68 парах, bench/absorb-calibration.json
7 мс
exit=0
```

**MCP** — настоящий `myc mcp` на stdio, JSON-RPC, тот же сценарий:

```
initialize: {"name":"myc","version":"0.2.2"}
myc_link text:
live-74986bas3r2m supersedes live-7hadmb4nn12y
effects   live-7hadmb4nn12y помечен superseded_by live-74986bas3r2m; старый узел сохранён · reason: перекалибровано на 68 парах, bench/absorb-calibration.json

myc_link structured: {"ok": true,
 "edge": {"from": "live-74986bas3r2m", "type": "supersedes", "to": "live-7hadmb4nn12y"},
 "effects": ["live-7hadmb4nn12y помечен superseded_by live-74986bas3r2m; старый узел сохранён",
             "reason: перекалибровано на 68 парах, bench/absorb-calibration.json"],
 "meta": {"took_ms": 5, "degraded": [], "seq": 40}}
```

**Граф после обоих прогонов** (прямой запрос к `edges`/`nodes`, не пересказ команды):

```
--- терминал (myc link) ---
CLI: ребро=[('supersedes', 1.0, None, '{"reason":"перекалибровано ..."}')]
CLI: attrs старого узла=live-gc70d5yx2qw8
--- MCP (myc_link) ---
MCP: ребро=[('supersedes', 1.0, None, '{"reason":"перекалибровано ..."}')]
MCP: attrs старого узла=live-74986bas3r2m

рёбра идентичны: True
```

Совпадают тип, вес, тумбстоун (`None` = живое), `attrs.reason` и след `superseded_by` на старом
узле. Автоматически то же самое проверяется на всех 9 типах, а не только на `supersedes`.

## Найдено попутно (не чинил — вне границ)

1. **`memory-gbp45ytdv6e6` (P2): сторож советуемых команд слеп к именам через подстановку.**
   `myc wire` в чистом проекте печатает ``WARN degraded.hook_missing: хук stop не поставлен:
   команды `myc close-session` нет в этой сборке``. Это пятое расхождение того же рода:
   `HOOK_SPECS` объявляет хук `stop` с `command: "close-session"`, команды в реестре нет.
   Сторож этого не видит **по устройству**: имя доезжает до текста подстановкой
   (`` `myc ${spec.command}` ``), а разбор литералов на `${…}` намеренно обрывается. Дыра не в
   регулярке — `HOOK_SPECS[].command` это тоже имя команды, названное пользователю, только через
   другую дверь. Дешёвая починка: сверять `HOOK_SPECS[].command` с реестром отдельной проверкой.
2. **`memory-5hxpgf1sh331` (P3): `dep rm` возвращает концы ребра в порядке ввода, `dep add` —
   нормализованные.** Наблюдаемо на `blocked-by`: `add` отвечает `{from: B, to: A}`, `rm` — 
   `{from: A, to: B}` про то же ребро. Паритет поверхностей НЕ нарушен (обе берут данные из
   одного `dep`), врёт только ответ, ребро снимается верное. `dep.ts` вне границ задачи.
