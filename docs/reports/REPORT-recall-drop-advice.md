## Что сделано

**Отсев считается ПО ПРИЧИНАМ там, где он и происходит** (не вторым проходом).
`packages/cli/src/commands/retrieve.ts`:

- `dropMaskOf(row, filters, repoWanted)` — единственное место постфильтра
  recall/search. Ранние `return false` сняты: строка помечается **битом
  каждого** сработавшего фильтра. Маска — одно целое число на строку, ноль
  аллокаций.
- Причины: `kind, since, until, tag, acl, author, anchor, reach, session,
  repo, several, dedup`. `layer` в списке **нет намеренно** — он живёт в SQL
  гибрида (`layerMin/layerMax` уходят в `federatedSearch`) и отсеивает **до**
  пула, то есть в дежурном списке он стоял вдвойне зря. При пустом пуле он
  теперь называется отдельным хвостом: `· поиск шёл под --layer L0`.
- `dropAdviceOf(drops, knobs)` — причина с наибольшим вкладом плюс готовая
  команда снятия. При равенстве вкладов выигрывает фильтр, стоящий в цепочке
  **позже**: такая строка прошла все предыдущие проверки, и снятие именно
  этого фильтра её вернёт наверняка. Два и более бита у одной строки — честное
  «несколько фильтров сразу — N: ослабляй по одному», без обещания, которое не
  сбудется.
- `emptyReasonOf(mode, pool, kept, drops, knobs)` — сигнатура расширена, старая
  строка-заглушка удалена.

**Флаг не выдумывается.** Новое поле `RetrieveRequest.knobs` — имена флагов
**самой команды**, взятые из её же `FlagSpec[]`:
`knobs: RECALL_FLAGS.map((s) => s.name)` в `recall.ts`, `SEARCH_FLAGS` в
`search.ts`. У `recall` `--repo` есть — совет говорит `сними: --repo all`. У
`search` его нет — совет говорит `сними: позови из корня экосистемы`.
Переименование флага в спецификации меняет совет само.

**Числа, а не только текст (И2).** `RetrieveOutcome.drops` и `RecallData.drops`
— полные счётчики по причинам в `--json`. Текст советует одну ручку; числа
показывают все, и это то, чем совет проверяется.

MCP-поверхность получает и подсказку, и `drops` **без правок**: `myc_recall`
зовёт CLI и отдаёт агенту человеческий текст плюс конверт.

## Что осталось

1. **`myc_recall` в MCP не умеет `--repo`** (`packages/mcp/src/dispatch.ts:586`,
   параметр отсутствует в схеме `packages/mcp/src/tools.ts`). Агент через MCP
   прочитает совет «сними: --repo all» и не сможет его исполнить — тот же класс
   бага, только на другой поверхности. Файл вне границ задачи; правка на
   полстроки в `argv` плюс поле в схеме.
2. **Дедуп как единственная причина пустоты недостижим**: он оставляет первую
   строку каждой группы, поэтому `kept = 0` при непустом `filtered` невозможно.
   Ветка совета для него написана и покрыта юнит-тестом, счётчик виден в
   `--json` и сверяется с `deduped`, но в подвал он попасть не может. Оставлено
   намеренно: порядок стадий может измениться, а молчащий счётчик — нет.
3. **`search` по-прежнему фильтрует по репозиторию без способа это снять
   флагом.** Совет теперь честен (зовёт в корень), но сам флаг `--repo` у
   `search` стоило бы завести — это расширение поверхности за рамками задачи.
