# Задача L — дренаж хвоста очереди jobs из жизненного цикла CLI (memory-90ynp9c15xqd)

Дата: 2026-09-05. Исполнитель: term_6a0f3cf9 / task_cffcb89e542f.

## Что сделано

Реализован механизм S8 («хвост очереди подхватывает следующий вызов CLI»), которого не
существовало ни в одной половине (S56):

- **`packages/cli/src/drain.ts` (новый)** — дренаж очереди:
  - дешёвые классы (`absorb`, `compact`) разбираются **инлайн по бюджету времени**
    (дефолт 50 мс на вызов, §12.2 D28; `MYC_DRAIN_BUDGET_MS`), проверка остатка —
    перед каждым захватом: взял работу, выполнил, проверил бюджет, вышел;
  - дорогой `embed` инлайн **не разбирается никогда** — поднимается отсоединённый
    `myc reindex` (приём `spawnEmbedDaemon`: spawn без await, detached + unref).
    Воркер конечен по устройству (разгрёб — вышел; ожидание соседа ≤ 2 аренд),
    поэтому второй утечки «демон пережил воркспейс» нет: ни TTL, ни сторожа db_gone
    не требуется. Не плодится, пока жива чужая аренда на embed; не поднимается без
    модели (та же привратность `modelLikelyPresent`, что у `warmInBackground`);
  - очередь — **только через `jobs`** из `@myc/store-sqlite` (`claim` с арендой,
    `complete`/`fail` ограждены holder); своего захвата нет;
  - дренаж — фон: никогда не бросает и не меняет результат команды; отказы видны
    через `jobs.last_error`/`stats`, не через чужой вывод;
  - соединение дренажа: `openDriver` с укороченным `busy_timeout = 250 мс`; HLC-join
    и site_id — дословно правила `openWorkspaceAt` (S38/S40-класс дефекта исключён);
    absorb-сессия без эмбеддера: вектор только из `nodes_vec`, иначе штатная громкая
    деградация в lexical (И2);
  - выключение: `MYC_DRAIN=0`; под тест-раннером (`process.env.NODE_ENV === "test"`)
    неявный дренаж выключен — иначе фон съедал очередь, которую in-process тесты
    (absorb.test.ts, whitelist-env) разбирают сами. Поймано прогоном полного сьюта.
- **`packages/cli/src/index.ts`** — вызов `drainAfterCommand(globals, options.env)`
  после успешного обработчика. Точки возврата без обработчика (`--version`, `--help`,
  usage-ошибки) до дренажа не доходят — их латентность не тронута.
- **`packages/cli/src/commands/absorb.ts`** — минимальная правка: `export` для
  `absorbOne` и интерфейса `Session` (два ключевых слова + комментарий). Отступление
  от списка «Трогаешь», обоснование: альтернатива — вызов команды absorb на каждую
  работу — платит открытием стора за работу и обходит `jobs.claim` (нарушение п.4).
- **`packages/cli/src/drain.test.ts` (новый)** — 8 тестов, включая обязательную
  многопроцессную гонку (8 реальных CLI-процессов × 40 работ) и e2e-приёмку.
- **`dist/myc`** — пересобран (`bun run build`); смоук на реальном воркспейсе пройден.

## Мутации — вывод по каждой

### 1. Убрана проверка остатка бюджета (`while (true)` — разбор до конца очереди)

`bun test` КРАСНЫЙ, как задумано:
```
(fail) бюджет дренажа > разбор прекращается по остатку бюджета, хвост очереди остаётся
  Expected: < 30 / Received: 30   (вся очередь разобрана при бюджете 35 мс)
```
Латентность CLI (30 absorb-работ × 5 мс, `myc list`): **243 мс** против 56 мс на
пустой очереди и 38 мс при `MYC_DRAIN=0`.

**`bench:latency` при этом ЗЕЛЁНЫЙ** — и это предметно важно: бенч меряет библиотечные
операции (prime/read/search/write на синтетической базе) и спавн `myc --version`, а
жизненный цикл команды он не наблюдает вовсе (`--version` возвращается до обработчика,
дренажа там нет). Формулировка «bench:latency обязан покраснеть» для этой мутации
невыполнима устройством бенча; мутацию ловит `bun test` (гейт) и замер латентности
команды. Если нужно, чтобы `bench:latency` сам сторожил бюджет дренажа, в него надо
добавить CLI-операцию (спавн `myc list` против базы с seeded-очередью) — отдельной
задачей, scripts/ вне моих границ.

### 2. `embed` разбирается инлайн (добавлен в INLINE_JOB_KINDS)

`bun test` КРАСНЫЙ:
```
(fail) инлайн-исполнители > embed инлайн НЕ разбирается … (мутация 2)
  expect(r.claimed).toBe(0) / Received: 1
```
Хуже задержки: без инлайн-исполнителя embed-работа **молча закрывается без выполнения**
— тихая потеря векторов, тот самый класс дефекта S56.

Бюджет `prime` (И1, 30 мс) нарушается измеримо: `myc prime` с 1 embed-работой по её
реальной цене (~50 мс) — **117 мс** против 66 мс без неё (одна работа уже больше всего
бюджета); 3 embed-работы при бюджете 1000 мс — **200 мс** против 66 мс. `bench:latency`
здесь тоже зелёный по той же причине (меряет библиотечный primeOp, не команду).

## Что осталось (не моё, фиксирую)

1. **`anchor_check` (7) и `distill` (9) не имеют исполнителей в репозитории вообще** —
   `packages/anchors` и `packages/distiller` заглушки. Их работы лежат в очереди
   незабранными: наблюдаемо через `jobs.stats`/`myc doctor`, не молча. Когда появится
   исполнитель — одна строка в `INLINE_JOB_KINDS` + ветка executor в drain.ts.
2. Личный ярус (`remember --global`, ~/.myc) дренаж не трогает: `drainAfterCommand`
   работает с проектной базой вызова. Отдельная задача, если нужно.
3. Инлайн-absorb не пишет `myc_health` (это делает команда `myc absorb` целиком):
   `doctor` увидит absorb-компонент по последнему явному прогону. Сознательно —
   минимальная поверхность правки absorb.ts.
4. S8 переписывать НЕ нужно: механизм «демон — опция» совместим с бюджетами (И1):
   разбор по бюджету 50 мс/вызов + конечный отсоединённый воркер для embed.
   Единственная поправка к тексту решений: `bench:latency` не наблюдает жизненный
   цикл CLI — гарантией бюджета дренажа служит `bun test` (drain.test.ts), а не бенч.
