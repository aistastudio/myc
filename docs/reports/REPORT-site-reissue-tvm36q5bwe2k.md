## 1. Мест оказалось пять, а не четыре

Задача называла четыре точки. `graft callers openWorkspaceAt --depth all` и
поиск по минту (`local-${…}` + `getRandomValues`) дали пятую:

```
packages/cli/src/commands/store.ts:508   openWorkspaceAt          (проектный и личный ярус)
packages/cli/src/commands/store.ts:1013  createPersonalWorkspace  ← НЕ БЫЛА В СПИСКЕ
packages/cli/src/commands/init.ts:323    createWorkspaceDb        (минт первого)
packages/cli/src/drain.ts:260            openDrainHandle          (фон)
packages/mcp/src/store.ts:255            openMcpStore             (долгоживущий сервер)
```

`createPersonalWorkspace` (`myc init --global`) создаёт `~/.myc/myc.db` **мимо**
`openWorkspaceAt` — «тому нужен уже существующий файл, а здесь файла заведомо
нет». Она читала существующий `site_id` и брала его как есть; для `--force`
(база пережила стирание кешей) это верно, а для `~/.myc`, приехавшего с другой
машины или из копии, — ровно тот дефект, который лечит S65. Теперь и она идёт
через `ensureSiteId`, и различие «взять старый / перевыпустить» делает не она, а
общее правило.

Файл лежит в границах задачи (`store.ts`), поэтому подключён, а не сведён в
раздел «за границами».

## 2. Форма подключения: одна последовательность, а не пять копий

Между чистым `decideSiteId` и местом открытия лежали шесть шагов: три чтения
`myc_meta`, решение, до четырёх записей, WARN. Пять копий этой
последовательности разъехались бы так же, как разъезжается всё продублированное.
Поэтому в `site-identity.ts` добавлено:

* `ensureSiteId({meta, dbPath, mint, warn?})` — читает, решает, пишет, говорит;
* `driverMeta(driver)` / `databaseMeta(db)` — доступ к `myc_meta` через драйвер
  и через голое соединение (`myc init` и личный ярус создают базу без драйвера);
* `mintSiteId(slug)` — форма нового идентификатора, прежде продублированная
  пять раз дословно;
* `META_SITE_ID`, `META_LAST_SEQ` — ключи (в `queries.ts` они приватные).

Вызов на всех пяти местах выглядит одинаково:

```ts
const { siteId } = ensureSiteId({
  meta: driverMeta(driver),   // или databaseMeta(db)
  dbPath,
  mint: () => mintSiteId(slug),
});
```

**Записей ровно столько, сколько изменений.** База, открытая на своём месте, —
ноль записей (проверено счётчиком в тесте: `existing` не пишет ничего). Стоимость
проверки — один `statSync`, 0.59 мкс по замеру предшественника.

**WARN громкий по умолчанию, а не по желанию вызывающего.** Параметр `warn`
необязателен, и его умолчание — `process.stderr`. Вызывающий, который про него
забыл, всё равно громкий; тесты подставляют свой сборщик. Для MCP это заодно
правильный канал: stderr не мешает JSON-RPC на stdout.

**`last_seq` при перевыпуске обнуляется**, и это часть решения, а не уборка.
`GraphStore` берёт `max(myc_meta.last_seq, seq последней СВОЕЙ операции)`; под
новым `site_id` в оплоге ещё нет ни одной операции, поэтому унаследованный
`last_seq` начал бы нумерацию с чужого места. Ключ продублирован из `queries.ts`,
и от расхождения страхует поведенческий тест: первая операция копии обязана быть
`<новый site_id>:1`.

## 3. Сторож полноты: `packages/cli/src/site-identity.wiring.test.ts`

Образец — `register.test.ts`: корпус собирается из исходника, а не
перечисляется, и намеренно не даёт себе стать пустым. Две половины.

**Половина 1 — поиск.** Сканируются `packages/*/src` (188 файлов, без тестов,
без `*.worker.ts`). Точкой открытия считается единица верхнего уровня, где
`site_id` может **родиться** (`mintSiteId(` либо старая форма `` `local-${ ``) или
**связаться с базой** (`new GraphStore(` / `new RepoScopedStore(`). Каждая
найденная единица обязана звать `ensureSiteId(`. Обе формы минта ищутся нарочно:
шаблон — это то, во что откатывается любая правка «сделать как было».

Комментарии из тела вырезаются ДО поиска, и это не косметика: первая версия
сторожа пропустила мутанта M2, потому что в `createPersonalWorkspace` стояло
прозаическое «решает ensureSiteId (S65)» и регулярка сочла это вызовом. Ровно от
этого предостерегает `register.test.ts` («не отличал бы зарегистрированное от
упомянутого в комментарии»); поймано мутацией, а не вычитыванием.

**Половина 2 — доказательство.** Текст лжив: вызов может стоять в мёртвой ветке.
У каждой найденной точки есть прувер — тест, который гоняет ЭТУ функцию на
копии базы (`cp -R`, новый инод) и смотрит на выданный `site_id`. Реестр
пруверов сверяется с результатом поиска **в обе стороны**: точка без прувера —
красный, прувер без точки — красный.

`openWorkspaceAt` проверяется через настоящую команду CLI (он не экспортирован —
и правильно, пользователь доходит до него только так); `openDrainHandle` для
этого пришлось экспортировать с пометкой `@internal`, как это уже сделано для
`openDriver`. У `createWorkspaceDb` перевыпуск невозможен по построению (база
новая), поэтому его прувер доказывает другое и не менее важное: вместе с
идентификатором записан ЭКЗЕМПЛЯР, и записанный инод равен настоящему иноду
файла. Без этой записи копия свежего воркспейса была бы **усыновлена обеими**
сторонами под одним `site_id` — то есть исходный дефект вернулся бы целиком.

Содержательное — падение прогона 2. Падает пункт 2 (порядок), пункт 1

Почему не моё, по коду: тест пишет операции ДВУМЯ отдельными процессами

открывается только В КОНЦЕ, на чтение. Решение о `site_id` физически не может
изменить порядок уже записанных операций. Мои записи идут в `myc_meta`, которую
`collectVersions` не читает.

В изоляции файл проходит **5 из 5**. На чистом HEAD (отдельный worktree,

## 8. Правка чужого теста, которую пришлось сделать

`packages/cli/src/commands/merge-driver.collision.test.ts` (тест предшественника)
падал после подключения — и это не регрессия, а его цель, достигнутая: тест
«`cp -R` копия воркспейса: merge падает» больше не воспроизводится через
настоящий CLI, потому что копия теперь получает свой `site_id` ДО того, как
выпишет хоть одну операцию.

Тест не удалён и не ослаблен. Столкновение осталось достижимым ровно для копий,
снятых **до** перехода: у таких баз нет записи об экземпляре, и `decideSiteId`
их усыновляет, а не перевыпускает (иначе переход раздробил бы `site_id` у всех
существующих воркспейсов разом). Поэтому в тесте перед копированием вызывается
`forgetInstance(dbPath)` — стирается `myc_meta.site_instance`, то есть
воспроизводится настоящее состояние дособытийной базы, а не подкручивается
поведение. Все прежние утверждения (код ≠ 0, «КОЛЛИЗИЯ op_id», обе версии целы
в индексе как `:2:` и `:3:`) остались дословно.

Рядом добавлен новый тест на сценарий приёмки — тот, что в §4.
