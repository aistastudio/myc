# W11 — Атрибуция исполнения (memory-c22bk5mdj2gq)

## Коротко

Записывать исход теперь стоит **один флаг**, а не шесть, потому что знание
разнесено туда, где оно уже есть: исполнитель открывает попытку (`myc attempt
start`, обычно вообще без флагов), координатор закрывает задачу вердиктом
(`myc close <id> --verdict accepted`). Модель обязана быть из ростера — барьер
стоит и в домене, и во внешнем ключе схемы. Стоимость замораживается на момент
попытки. Вопрос задаётся командой `myc report models` и отвечается по классам
задач, с интервалами доверия и с явным признанием там, где данных не хватает.

## Что сделано

### Схема (миграции 003–005, `packages/swarm/src/migrations/`)

| Версия | Объект | Зачем |
|---|---|---|
| 003 | `swarm_attempt` | попытка: задача, модель (FK на `swarm_model`), харнесс, уровень, класс задачи, вердикт, оговорки, токены, **замороженная** стоимость и строка цены, по которой считали |
| 004 | индекс `swarm_attempt_task` | `myc close` ищет открытую попытку задачи на каждом закрытии |
| 005 | индекс `swarm_attempt_arm` | группировка `(task_class, model_id, effort)` — ключ вопроса и будущего роутера |

Один оператор на миграцию; колонки `quality` нет сознательно — качество это
формула над `verdict`+`caveats`, её веса живут в коде и версионируются
`OUTCOME_VERSION`, чтобы отчёт всегда мог сказать, по какой формуле считал.
Стоимость, наоборот, хранится: это факт о прошлом.

### Честность данных: вердикт + оговорки, а не «успех/провал»

```
verdict:  accepted (1.0) | rework (0.5) | rejected (0)
caveat:   coordinator_fixed (−0.35)  — координатор доделал сам
          tests_weak        (−0.40)  — тест проходит и на сломанной реализации
          report_inaccurate (−0.25)  — находка агента не подтвердилась
          scope_missed      (−0.30)  — часть заявленного объёма не сделана
q = max(0.1, base − Σ штрафов);  rejected = 0 при любых оговорках
```

Это ровно те четыре случая, которые координатор назвал живыми примерами дня.
«Принято с оговорками» даёт q от 0.60 до 0.10 — и это **меняет ответ на
вопрос**, а не только поле в строке (мутация 1 ниже).

### Класс задачи (`packages/swarm/src/taskclass.ts`)

`intent × scope` по §2.1.3–2.1.4: три источника намерения в порядке приоритета
(явное поле → тип `bug` → лексикон заголовка → форма якорей), scope по якорям.
Детерминирован, версионирован `FP_VERSION`, без сети и без LLM. `graft` не
зовётся: депт (`fan-in`) взят нулём, разница с полной формулой только в том,
что одиночный файл с большим fan-in назовётся `local`, а не `module`.

### Вопрос (`packages/swarm/src/compare.ts`, `myc report models`)

«Дешевле при равном результате» разложено на три отдельных механизма:

- **на каком классе** — группировка по `task_class`;
- **при равном результате** — НЕ равенство средних. Качество руки —
  апостериор `Beta(1+Σq, 1+Σ(1−q))`, «равный результат» = пересечение
  90 % интервалов с лидером. Реализована регуляризованная неполная
  бета-функция (непрерывная дробь Лентца) и квантиль делением пополам;
- **дешевле** — по замороженной стоимости и только по попыткам, где она
  посчиталась; доля таких попыток (`costCoverage`) печатается.

Ответ, который не опирается на данные, называется вслух:
`insufficient_attempts` / `single_arm` / `no_cost_data` / `ok`. Отдельный флаг
`separationPending` = «дешёвая рука победила не потому, что так же хороша, а
потому, что наблюдений пока не хватает, чтобы её отличить».

### CLI

```
myc attempt start  <task-id> [--model|$MYC_MODEL] [--class] [--tokens-in/out]
myc attempt finish [<attempt-id>|--task <id>] --verdict … [--caveat a,b]
myc attempt list | show
myc close <id> --verdict accepted|rework|rejected [--caveat …] [--model …]
myc report models [--class intent:scope] [--since 30d] [--min N]
```

У `myc attempt list` свой плотный вывод — по строке на попытку вместо
дефолтной таблицы в 21 колонку (замечание координатора по `myc model list`
из W10 сюда не повторено).

`myc close` закрывает открытую попытку задачи; если попытки нет, но названа
модель — заводит и закрывает разом. Ничего не записалось — сказано вслух
(`attribution.open`, `attribution.no_model`, `attribution.env_model` в `warn[]`
и строкой «атрибуция НЕ записана» в человеческом выводе).

### Три находки на настоящих данных, которые важнее кода

**1. Диагноз координатора подтверждается полностью и с запасом.** Из 86
закрытых задач `outcome.model` заполнен у **0**, `outcome.verify` у **0**,
`outcome.outcome` у **0**. Причина закрытия текстом есть у всех 86.

**2. Ростер, принятый сегодня, в этом воркспейсе пуст — таблиц `swarm_*` в
`.myc/myc.db` нет вообще.** Тот же самый сюжет «схема без способа наполнения»,
на день позже. Мой вывод: любая новая схема обязана приезжать вместе с
командой, которая её наполняет по ходу обычной работы, иначе она пустая.

**3. Утверждение из постановки «модель названа словами» на этом корпусе НЕ
подтвердилось.** Прогнал все 86 текстов причин закрытия (83 922 символа) по
именам моделей: `sonnet|opus|haiku|glm|kimi|codex|gpt|qwen|deepseek|minimax|grok`
— одно совпадение, `kimi`, и то внутри перечисления допустимых харнессов.
Модель в этих текстах не называется ни разу. Корпус годится как источник
**вердиктов** (17 вхождений «Принято», 44 «мутац», 4 «не подтвердил», 2 «не
ловит», 1 «не охраняет»), но не как источник моделей. Поэтому обратной
засыпки атрибуции по существующим текстам я не делал: она свелась бы к
угадыванию исполнителя, а выдуманные данные хуже отсутствующих.

### Класс задач на настоящих заголовках

Прогнал `computeTaskClass` по всем 86 закрытым задачам с настоящими
заголовками, типами и якорями:

Честная оценка: **лексикон срабатывает только на 10 из 86 заголовков (12 %)**,
48 падают в остаточный класс `feature` через якоря. Причина видна на глаз:
заголовки здесь — именные формулировки проблемы («Хвост очереди не подхватывает

(таблица `anchors` пуста, `attrs.anchors` есть у 1 узла из 258). Ось класса
работает, но грубо; чинится расширением лексикона именными основами в
`fp_version = 2` и появлением якорей у задач — не выдумкой scope.

## Мутации

Ломал свою реализацию, каждый раз показывая покраснение.

**Мутация 1 — свести «принято с оговорками» к успеху** (`qualityOf` игнорирует
`caveats`): **9 падений**.

```

  expect(cls.arms.find(a => a.modelId === "p/cheap")!.qualityMean).toBeCloseTo(0.25)

(fail) report models > та же дешёвая модель с оговорками ответ НЕ выигрывает

… ещё 6
47 pass, 9 fail
```

Отдельным тестом зафиксировано, **на чём именно врёт запрос**: если стереть
оговорки у уже записанных попыток, ответ на вопрос переворачивается с дорогой
руки на дешёвую (`compare.test.ts`, «если оговорки свести к успеху»).

**Мутация 2 — позволить записать модель мимо ростера** (снят доменный барьер в
`startAttempt`): **1 падение**, и оно показывает второй барьер:


Барьеров два намеренно: доменная проверка (внятный код и подсказка) и внешний
ключ схемы при `PRAGMA foreign_keys=ON` (защита от прямого INSERT). Снятие
одного не разрывает связь молча.

**Мутация 3 — считать стоимость по текущей цене вместо цены на момент попытки.**

## Многопроцессный тест

`attribution.race.test.ts` — 6 процессов `Bun.spawn` одновременно закрывают
ОДНУ попытку и параллельно открывают свои. Инварианты: победитель ровно один
(остальные получают `conflict.finished`, а не перетирают чужой вердикт),
записан исход победителя целиком, шесть параллельных стартов не потеряны,
учёт миграций без дублей.

Тест поймал настоящий дефект в собственном воркере: `PRAGMA journal_mode=WAL`
до `busy_timeout` даёт «database is locked» мимо busy-handler (тот же урок, что
в `roster.race.worker.ts`). Порядок исправлен, после этого 5 прогонов подряд
зелёные.

## Что осталось нерешённым

1. **Токенов не даёт никто, и без них половина вопроса не отвечается.** Все
   механизмы стоимости работают, но `cost_basis` у сегодняшних записей —
   `no_tokens`. Нужен поставщик: хук харнесса, экспортирующий
   `MYC_TOKENS_IN/MYC_TOKENS_OUT`, либо `myc attempt finish --usage <json>`
   рантайма. Пока его нет, `report models` честно отвечает `no_cost_data` —
   но отвечает «не знаю», а не «дешевле такая-то».
2. **MCP-поверхности у атрибуции нет.** Агенты закрывают задачи через MCP, а
   `packages/mcp/` вне моих границ. Пока агент, работающий через MCP, вердикт
   записать не может — а это большинство исполнителей. Нужен инструмент
   `myc_attempt`/`verdict` в профиле agent.
3. **`myc bootstrap` не рассказывает про цикл атрибуции.** Строка `loop:`
   зашита в `packages/cli/src/commands/bootstrap.ts` (вне границ). Команды
   `attempt` и `report` в автодетект `cmds:` уже попали. Пока проще всего
   закрыть это без кода:
   `myc bootstrap set attribution "исполнитель: myc attempt start <id> ($MYC_MODEL); координатор: myc close <id> --verdict accepted|rework|rejected [--caveat tests-weak,…]; вопрос: myc report models"`
4. **`strengths` в ростере по-прежнему заполняется рукой.** Мой отчёт — ровно
   тот источник, который должен его наполнять («место под знание, которого
   пока нет», из W10). Писателя нет.
5. **Отложенные сигналы (§2.3.4) не реализованы**: `reverted`, `reopened`,
   `redone`, `followup_bug`. Сейчас исход — это вердикт координатора в момент
   закрытия, и только он. Переоткрытая через неделю задача статистику не
   поправит.
6. **Лексикон отпечатка** (см. измерение выше): 12 % срабатывания на настоящих
   заголовках, `fp_version = 2`.
7. **Один полный прогон `bun test` из восьми показал 1 падение**, имя теста я
   не зафиксировал (грепал уже следующий прогон). Семь остальных полных
   прогонов — 0 падений; гоночный тест атрибуции отдельно 5 прогонов из 5
   зелёный. Называю прямо, а не умалчиваю: возможен флейк, источник не
   установлен.

## Мелочи, замеченные по дороге

- Гоночный тест поймал в моём же воркере порядок PRAGMA (см. выше) — тот же
  дефект, что уже был исправлен в `roster.race.worker.ts`. Комментарий с
  причиной перенесён и в мой воркер, чтобы третий раз не наступили.
- `ensureSwarmSchema` теперь имеет быстрый путь без транзакции записи; без
  него каждое чтение отчёта брало бы блокировку записи.
- Если исход не записался УЖЕ ПОСЛЕ смены статуса задачи (гонка или неверное
  число кругов доработки), команда не притворяется, что ничего не произошло:
  задача закрыта, `warn` `attribution.failed` назван, под `--strict` это код
  выхода 7.
