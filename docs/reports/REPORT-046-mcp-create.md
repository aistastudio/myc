# 0.4.6 — `myc_create` в MCP и честный отказ `myc_update`

Инцидент (скриншот из проекта GigaAM, 2026-10-09): агент вызвал `myc_update` с
`operation={action:"create", parent_id:null, summary:"…"}` и без `id`, получил
«missing parameter id», вторым вызовом повторил то же с чуть иной формой и
заключил: «MCP-обёртка update сломана для create — продолжаю через CLI». Две
независимые причины; исправлены обе, релиз 0.4.6 в worktree `main`
(`/Users/egortaranin/src/memory-main`).

## 1. Причина 1 — порядок валидации в `toolUpdate`

`packages/mcp/src/dispatch.ts`: `id` требовался ДО проверки `op`, поэтому любой
вызов с чужой формой получал «missing parameter id» вместо настоящего промаха.
Теперь порядок такой: `op` → human-only (`cancel`) → список разрешённых → `id`.
Отказ «invalid op» получил hint с законным путём:

```
myc: usage.invalid: invalid op 'create'; allowed: claim, release, close, …
hint: myc_update only changes the state of an EXISTING node: to create one use
      myc_create, to record a conclusion or fact use myc_remember
```

Сторож: тест «op=create отвечает "нет такой операции" ДО требования id и зовёт
выход» (`dispatch.test.ts`). Доказательство мутацией — возврат
`const id = reqStr(args, "id")` наверх функции роняет тест (проверено 2026-10-09:
мутация 1 fail, восстановление 30 pass). Второй тест фиксирует точную форму из
инцидента (`operation={…}` без `op`) → «missing parameter 'op'», и что ни одной
команды CLI при отказе не выполнено.

## 2. Причина 2 — создания через MCP не было вовсе

Профиль agent не умел заводить узлы: в §4.2 дизайна исполнитель «должен уметь
ровно четыре вещи», создания нет, и агент, которому нужно завести задачу,
вынужден был выдумывать вызов или уходить в CLI. Добавлен тул **`myc_create`**
(ИМЯ = КОМАНДА CLI, как у инструментов кода): обработчик переводит аргументы в
argv `myc create` и не валидирует ничего сам — проверку kind и приоритета ведёт
команда, паритет argv проверяется тестами (`myc_create: argv — та же команда`,
4 теста). Поверхность: `title` (обязателен), `kind` (default task),
`priority`, `parent`, `dep[]`, `assign`, `body`, `tag[]`. `--anchor`, `--repo`
и body через stdin MCP не выданы: якорь исполнителю ставит хук, охват
репозитория выводится из каталога (§4.6.1).

## 3. Бюджет D7 — обоснование числами

D7 пускает новый тул «вместе с удалением другого или письменным обоснованием»,
обоснование — число:

| Замер (оценщик tokens.ts, ceil(chars/3)) | до | после | потолок |
|---|---|---|---|
| Описания WORK_TOOLS | 953 токена (2858 симв.) | **1061 токен (3181 симв.)** | 1100 — НЕ поднят |
| Профиль agent целиком | 13 тулов | 14 тулов | 1827 — не поднят |

Налог сессии вырос на 108 токенов оценки. Другой тул не удалён. Оправдание:
каждый инцидент «агент выдумывает create» стоил дороже — два и более
бесполезных вызова плюс ложное belief «обёртка сломана», которое агент унёс в
отчёт. Тест `описания инструментов работы <= 1100 токенов` проходит без
изменения константы.
