# myc — общий бриф проектирования

> Это общий контекст для всех воркеров дизайн-сессии. Прочитай целиком, потом
> открой свой лейн-файл (см. «Лейны») и пиши **только его**.

## 1. Что проектируем

**myc** (mycelium, CLI: `myc`) — быстрый слой **задач + памяти + связей** для ИИ-агентов.
Один граф, который держит: что делать (задачи с зависимостями), что известно
(память/знания), к какому коду это привязано (якоря), и кто как справляется
(телеметрия роя).

Работает: локально из CLI, как MCP-сервер, и как сервер для команды.
Стек: **Bun + TypeScript**, хранилище **SQLite (embedded, по умолчанию)** и
**PostgreSQL (server/team)**. Запуск в контейнерах. Веб-интерфейс визуализации.

**Главное требование — скорость.** Утилита стоит в горячем пути агента:
её дёргают десятки раз за сессию. Всё, что не укладывается в бюджет
латентности, идёт в фон.

## 2. Решения, уже принятые заказчиком (не пересматривать)

| Решение | Значение |
|---|---|
| Имя | `myc` / mycelium |
| Рантайм | Bun + TypeScript, один бинарь (`bun build --compile`) |
| Хранилище | SQLite embedded по умолчанию; PostgreSQL для сервера/команды |
| Эмбеддинги | **Локальные по умолчанию** (ONNX в процессе Bun), API — опциональный бэкенд |
| Код-граф | **Не пишем свой.** Свои якоря `file:line + blob_hash` + адаптер поверх **graft** |
| Интерфейсы | CLI + MCP + HTTP API + веб-визуализация |
| LLM-провайдеры | OpenAI- и Anthropic-совместимые API (как в memora) |
| Деплой | Локально без демона; сервер в Docker/compose |

## 3. Бюджеты (проектируем под них, не «оптимизируем потом»)

- `myc prime` (бутстрап контекста в начале сессии): **p99 < 30 мс**, холодный старт процесса **< 60 мс**.
- Точечное чтение (`show`, `get`): **p99 < 3 мс** локально.
- Гибридный поиск по 100k узлов: **p99 < 25 мс** локально (включая эмбеддинг запроса).
- Запись (`create`, `remember`): **p99 < 5 мс**, вся тяжёлая обработка (эмбеддинги, absorb-классификация, суммаризация) — **асинхронно**, запись не ждёт.
- Сеть в горячем пути: **запрещена** в дефолтной конфигурации.
- `$0` по умолчанию: без API-ключа утилита обязана работать полностью, теряя только LLM-обогащение.

## 4. Что берём из источников

### beads (`bd`) — слой задач
Граф задач вместо markdown-планов. Приоритеты P0–P3, типы (task/bug/epic/message),
статусы, **иерархические хеш-ID** (`bd-a3f8.1.1`) — не конфликтуют при мерже веток.
Типы рёбер: `blocks`/`blocked-by`, `relates-to`, `duplicates`, `supersedes`, `replies-to`.
Ключевая операция — **`bd ready`**: задачи без открытых блокеров (граф-запрос, который
даёт агенту право взять работу без разбора). Атомарный `claim` (assignee+in_progress)
против гонок между агентами. `bd prime` — впрыск воркфлоу-контекста и памяти в начало
сессии, `bd remember` — заметка проекта. **Semantic memory decay**: старые закрытые
задачи сжимаются в саммари ради экономии контекста. Хранилище — Dolt (SQL с cell-level
merge и ветками), JSONL — только экспорт. Сообщения между агентами как тип сущности с тредами.
> **Берём:** ready-очередь, атомарный claim, хеш-ID, типы рёбер, prime/remember, decay,
> сообщения-как-узлы. **Не берём:** зависимость от Dolt (тяжело, отдельный движок).

### memora — слой памяти
MCP-память с дедупликацией и графом. Типы: memory, TODO, issue, document
(парсится на типизированные фрагменты: claims / plan_items / references / risks),
section. **`absorb`**: входящий факт классифицируется LLM как duplicate / update /
contradiction / related / new — не пишем мусор, ведём линию наследования.
**Supersession** с режимами `active` / `full_history`. **`memory_digest(topic)`** —
собрать по теме факты + открытые действия + рёбра + источники.
Поиск: semantic / full-text / hybrid + фильтры по датам и тегам.
Профили инструментов: full (43) / leader (19) / agent (12) — разный набор MCP-тулов по роли.
Мульти-БД в одном процессе, cloud-бэкенды (D1, S3/R2), health-эндпоинты, веб-граф с Mermaid и SSE.
> **Берём:** absorb-конвейер, supersede-с-историей, digest, профили инструментов, health, веб-граф.
> **Ловушка, которую обязаны закрыть:** у memora при недоступности эмбеддингов —
> **молчаливый фолбэк на TF-IDF**, база наполняется мусором и «выглядит здоровой».
> У нас деградация должна быть **громкой и видимой в статусе**.

### TencentDB-Agent-Memory — слоистость и управление
**L0 conversation → L1 atom → L2 scenario → L3 core/persona.** Генерация и ретривал
оба слоистые: обычно L2/L3 дают быстрый бутстрап контекста, а за конкретными фактами
падаем в L1/L0 через **BM25 + вектор + RRF**. Активы: chat memory, **skills**
(версионируемые исполняемые воркфлоу с триггерами и валидацией), **wiki** (документы
со связями), **codegraph**. Ретривал **по требованию**, а не «влить всё»: лимиты по
количеству, символьному бюджету и таймауту. ACL: private / team / restricted / agent,
фильтрация до ранжирования. **Memory Proxy** — OpenAI-совместимый эндпоинт, который
подмешивает память в запросы агента без правки его кода.
> **Берём:** L0–L3, RRF, бюджеты ретривала, ACL до ранжирования, skills как сущность,
> proxy-режим. **Осторожно:** асинхронная дистилляция обязана быть отменяемой и дешёвой.

### graft — код-граф (мы его НЕ переписываем)
Двухпроходный: tree-sitter (детерминированно, $0, без сети) + опционально LLM-обогащение.
Узлы — markdown с summary/crux/sources/links; **crux хранится как текст, а не номера строк** —
переживает рефакторинг. Свежесть по content-hash, рефреш рабочего дерева ~3 мс перед
каждым запросом. CLI: ask/grep/skeleton/callers/map/blast/check. MCP: 6 инструментов.
Заявленный эффект: −23% токенов, −25% вызовов, −32% времени, +12 п.п. корректности на SWE-bench.
> **Берём как зависимость/адаптер.** Наш вклад: якоря `repo+path+span+blob_hash`,
> детект протухания, двусторонняя связь «память/задача ↔ символ кода».
> **Идея crux-как-текст переносим на наши якоря.**

### socraticode — гибридный поиск и артефакты контекста
AST-aware чанкинг (границы функций/классов), dense (Ollama/OpenAI/Gemini) + sparse (BM25),
**RRF в один round-trip** к Qdrant (HNSW). Полиглот-граф импортов через ast-grep, циклы,
blast-radius, call-flow. **Context artifacts**: SQL-схемы, OpenAPI, k8s-манифесты, доки —
чанкуются и ищутся рядом с кодом. Инкрементальная **возобновляемая** индексация батчами
по 50 с чекпойнтами и хешами. Watch с дебаунсом 2 с. Мультиагентный доступ к одному
индексу через файловые локи, branch-aware индексы. 61% меньше контекста, 84% меньше
вызовов, 37× быстрее grep на 2.45M строк.
> **Берём:** RRF-фьюжн одним проходом, context artifacts, возобновляемую индексацию с
> чекпойнтами, branch-aware, мультипроцессный доступ. **Не берём:** Qdrant как
> обязательную зависимость — у нас векторный поиск должен жить внутри SQLite/Postgres.

## 5. Пятая подсистема (нашего изобретения): самообучение роя

Заказчик добавил требование: **myc копит статистику «какая модель какие задачи тянет»
и роутит работу по цене/качеству.**

Идея: каждая задача, отданная агенту, порождает запись исхода — отпечаток задачи
(класс, домен, размер диффа, языки, репозиторий), выбранная модель и уровень усилий,
стоимость (токены in/out, $), время, исход (успех / провал / переделка), сигнал
верификации (тесты, ревью, принял ли человек, откатили ли коммит), число ретраев.
Из этого выводятся приоры «модель × класс задачи» и политика роутинга
(`myc route <task>` → модель + усилия + ожидаемая цена и уверенность).
Приоры общие для команды через сервер. По умолчанию пишем **только метаданные, не контент**.

## 6. Не-цели

- Не пишем свой векторный движок и свою БД.
- Не переписываем graft/socraticode.
- Не строим оркестратор агентов: myc даёт **память, задачи и рекомендации по роутингу**;
  запускает агентов внешний инструмент (Orca, Claude Code, opencode).
- Не тянем облачные бэкенды в MVP (D1/S3) — только SQLite и Postgres.

## 7. Формат результата каждого воркера

Пиши **строго свой файл** (см. ниже), на русском, markdown. Никаких других файлов не трогай.
Структура:

1. **Решения** — таблица «вопрос → выбор → почему → что отвергли».
2. **Спецификация** — конкретно: схемы, сигнатуры, алгоритмы, псевдокод.
   Не «нужен кэш», а «LRU на 512 записей, ключ = hash(query)+scope, инвалидация по oplog seq».
3. **Бюджеты и как их держим** — где именно тратится латентность, что в фоне.
4. **Риски и что ломается на масштабе.**
5. **Открытые вопросы координатору** — то, что пересекается с чужим лейном.

Требования к содержанию: DDL/типы приводить целиком; алгоритмы — псевдокодом;
все константы называть числом. Опирайся на то, что уже решено в §2 и на бюджеты §3.
