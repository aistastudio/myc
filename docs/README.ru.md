# myc

Локальный, быстрый слой задач и памяти для кодогенерирующих агентов: очередь
задач, оплог фактов и решений, гибридный (лексика + вектор) поиск по памяти
проекта — без сети и без обязательного LLM-ключа. Дизайн подробно описан в
`docs/design/` (начать с `docs/design/00-brief.md`), рабочие измерения по
конкретным задачам — в `docs/reports/`.

## Требует Bun — это не мелкий шрифт

Рантайм жёстко завязан на `bun:sqlite` (SQLite и `sqlite-vec` встроены в Bun,
без нативных биндингов на стороне Node). На момент этого README `bun:sqlite`
импортируют 34 файла рантайма — хранилище, CLI, MCP-сервер, web, swarm.
**На голом Node.js или Deno проект не запустится.** Нужен Bun ≥ 1.3.0
(зафиксировано в `package.json` → `engines.bun`).

Установка Bun: https://bun.sh

## Установка

```bash
bun install -g @aistastudio/myc   # 3.20 МБ, 10 файлов, модели при установке не тянутся
myc --version                     # myc 0.3.3 (schema 1)
```

Модель эмбеддингов при установке **не** скачивается. Семантический поиск
включается явно: `myc models fetch` (129 МБ, ~7 с). До этого поиск лексический,
и он об этом говорит.

Чтобы работать с кодом свежее опубликованного релиза — собрать из исходников:

## Быстрый старт

```bash
bun install
bun run build           # собирает один бинарь: dist/myc (dist/ не в git)

# инициализировать воркспейс в текущем репозитории: .myc/ + sqlite + миграции
./dist/myc init

# поставить хуки для Claude Code / Codex / opencode / Kimi (агент сам подхватит контекст)
./dist/myc wire

# по желанию — строка статуса Claude Code: очередь, индекс кода, память, полезные обращения сессии
./dist/myc wire --status-line

# по желанию — хук, который сам ставит тяжёлые команды агента (полный bun test, сборки) в очередь машины
./dist/myc wire --queue-hook

# что можно взять в работу прямо сейчас
./dist/myc ready

# проверить состояние: схема, счётчики, хуки — там, где не знает, так и говорит
./dist/myc doctor

# записать факт или решение в память проекта
./dist/myc remember "почему выбрано X, а не Y"

# найти по памяти своими словами
./dist/myc recall "как устроен ретривал"

# стартовый пакет контекста сессии (обычно вызывается агентом автоматически)
./dist/myc prime
```

Полный список команд: `./dist/myc --help`, детали каждой — `myc <command> --help`.

## Тяжёлые команды — по очереди

Несколько агентов на одной машине гоняют тяжёлое одновременно — полный прогон
тестов, сборки, бенчмарки — и мешают друг другу: прогоны идут вдвое дольше,
бюджеты задержек падают из-за соседа, а не из-за кода. `myc run -- <команда>`
ставит команду в общую для всех репозиториев машины очередь
(`~/.myc/queue.db`), ждёт слот и выполняет её с тем же терминалом и тем же
кодом выхода; `myc queue` показывает, кто выполняется и кто ждёт. Ждущий пишет
в stderr, кого ждёт, а после `--max-wait` (по умолчанию 5 мин) сдаётся с кодом
9 и называет, кто впереди. Упавший держатель (даже по `SIGKILL`) слот
освобождает; вложенный `myc run` идёт сразу, в слоте предка.

Помнить об этом агенту не нужно: `myc wire --queue-hook` ставит Claude Code хук
`PreToolUse`, который переписывает тяжёлую Bash-команду в
`myc run -- <та же команда>`. Тяжёлое — полный прогон тестов и сборка (`bun
test` без путей, `bun run build`/`typecheck`, `npm`/`pnpm`/`yarn test`,
`cargo test`/`build`, `go test ./...`, `pytest` без путей, `make`); точечный
`bun test path/file.test.ts`, уже обёрнутое, фоновое и вложенное не трогается,
список переопределяет `MYC_QUEUE_HEAVY`. Только по флагу. Лёгкую команду
отпускает сам shell хоста, не запуская ни bun, ни node.

`myc run` исполняет что угодно, поэтому обходом прав он не служит: команда в
очереди проходит без вопроса, только если ваши правила пропустили бы исходную
(`Bash(bun test:*)` оставляет `bun test` без вопроса и в очереди); иначе Claude
Code спрашивает, и в вопросе видна вся команда, а deny/ask-правило исходной
команды действует как прежде. Так же судится `myc run -- <команда>`, набранный
агентом. По той же причине `wire` больше не пишет широкое `Bash(myc:*)`: он
разрешает подкоманды myc по одной, а `run`, `statusline --then`, `wire` и
`unwire` спрашивают.

## Что уже работает

Числа — закрытые/все подзадачи эпика (`myc show <epic-id>`) на 2026-09-10,
не оценка на глаз; могут разойтись с текущим состоянием — проверяйте `myc list`.

- **M0 — ядро и задачи** (40 из 43): оплог, HLC, граф узлов/рёбер, SQLite,
  атомарный `claim`, ready-очередь, CLI. **M0.5** — myc разрабатывается через
  myc (4 из 4, закрыта).
- **M1 — память** (22 из 24): `remember`/`recall`, absorb (детерминированная
  классификация без LLM), FTS5-поиск, `prime`, обязательный хук PreCompact —
  сессия агента переживает сжатие контекста без потери решений; память
  разделена по сессиям, и это видно в выдаче.
- **M2 — семантика** (20 из 22): локальные ONNX-эмбеддинги, гибридный
  ретривал (RRF), векторное хранилище `sqlite-vec` — поиск по смыслу в
  бюджете 25 мс на 100k узлов.
- **M3 — код** (6 из 10): встроенный код-интеллект на tree-sitter, грамматики
  качаются по требованию. Символы, callers и поиск по коду — для TypeScript,
  TSX, JavaScript (js, jsx, mjs, cjs) и Python: для них есть правила разбора
  определений; в пакете грамматик их 36, но язык добавляется парой — правило и
  строка каталога. Остальным файлам доступны `code grep`, якоря и протухание.
  `myc code index` строит индекс, читают его:

  ```
  myc code symbol <имя>    где определено и какое знание к этому привязано
  myc callers <имя>        кто зовёт; --direction out, --depth all
  myc code search "…"      по смыслу, когда имя неизвестно
  myc code grep "<лит>"    все вхождения; --in <путь> сужает область
  myc skeleton <файл>      API файла — дешевле, чем читать его целиком
  ```

  Перечень файлов — от самого git (`git ls-files`, то есть с `.gitignore`;
  дерево без git обходится, и команда об этом говорит). Поверх любого перечня
  файлы с секретными именами не индексируются никогда, что бы ни было в
  `.gitignore`: `.env` и `.env.*` (шаблоны вроде `.env.example` индексируются),
  `*.pem`, `*.key`, хранилища ключей, приватные ключи SSH, `.npmrc`, `.netrc` и
  другие файлы учётных данных — `code index` называет их число, но не имена, а
  `code grep` читать такой файл отказывается.

  Якоря привязывают знание к участку кода и следуют за ним при правках.
- **M7 — интерфейс человека** (15 из 15): доска, карточки, обсуждения, панель
  роутинга и строка статуса Claude Code (`myc wire --status-line`). Строка
  показывает заполненность контекста, очередь задач, индекс кода, память проекта и сколько обращений к
  myc в этой сессии дали результат — по транскрипту хоста, а не на глаз.
  Прежнюю строку статуса она не вытесняет: та получает тот же ввод, её не ждут
  и не убивают.

## Синхронизация между машинами

В git идёт только оплог (`myc export` → `.myc/graph`, `myc import` при клоне) —
не производные проекции и не кеши. `.myc/workspace.toml` и оплог в
`.myc/graph` коммитятся намеренно; `.myc/myc.db*`, локальные кеши и рантайм-
состояние — нет (см. `.gitignore`).
