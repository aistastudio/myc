myc

A local task-and-memory layer for coding agents: a task queue, an oplog of facts and decisions, and hybrid search over a project's memory. No network calls, no mandatory LLM key.

Локальный слой задач и памяти для кодовых агентов: очередь задач, оплог фактов и решений, гибридный поиск по памяти проекта. Без сетевых вызовов и без обязательного ключа к модели.

Agents forget. myc is the part that doesn't: decisions survive context compaction, work survives process death, and both survive being moved between machines through plain git.

Агенты забывают. myc — та часть, которая нет: решения переживают сжатие контекста, работа переживает смерть процесса, и то и другое переезжает между машинами обычным git.

01

Install

Установка

One command, one binary, no models pulled. Semantic search is opt-in and says so until you enable it.

Одна команда, один бинарь, модели при установке не качаются. Семантический поиск включается отдельно и до тех пор честно говорит, что его нет.

Requires Bun — this is not fine print

Требуется Bun — и это не мелкий шрифт

The runtime is bound to bun:sqlite: SQLite and sqlite-vec ship inside Bun, with no native bindings on the Node side. It will not start on plain Node.js or Deno. Bun ≥ 1.3.0, pinned in engines.bun.

Рантайм привязан к bun:sqlite: SQLite и sqlite-vec едут внутри Bun, нативных биндингов на стороне Node нет. На чистом Node.js или Deno он не стартует. Bun ≥ 1.3.0, зафиксирован в engines.bun.

$curl -fsSL https://bun.sh/install | bash

Then myc itself

Дальше сам myc

$bun install -g @aistastudio/myc

Quick start

Быстрый старт

Five commands is the whole loop an agent lives in.

Пять команд — весь цикл, в котором живёт агент.

myc init      # .myc/ + SQLite + migrations in this repo
myc wire      # hooks for Claude Code / Codex / opencode / Kimi

myc recall   "how retrieval works"

Semantic search is opt-in

Семантический поиск — по запросу

$myc models fetch multilingual-e5-small-q8

Until you run it, search is lexical (BM25) and says so out loud on every degraded answer: WARN degraded.embeddings. The invariant is that a degraded answer must never be indistinguishable from a healthy one.

До этого поиск лексический (BM25) и говорит об этом вслух в каждом ухудшенном ответе: WARN degraded.embeddings. Инвариант такой: ухудшенный ответ не имеет права быть неотличимым от здорового.

03

Ranking is measured, not asserted

Ранжирование измеряется, а не декларируется

Two labelled corpora with graded relevance. Each one contains a control group that gets worse when the feature works — so the gain cannot be manufactured by shaping the corpus.

Два размеченных корпуса с градуированной релевантностью. В каждом есть контрольная группа, которая при верной работе ухудшается — поэтому выигрыш нельзя получить, подогнав корпус.

Why a control group that gets worse is the point

Зачем нужна группа, которой становится хуже

A boost that lifts priority, freshness and layer must push down a document that matches the words but is stale and low-priority. If every group improved, the corpus would be telling us what we already wanted to hear. The distractor group is the falsification test: it is expected to drop, and it drops.

Буст, который поднимает приоритет, свежесть и ярус, обязан опустить документ, который совпал словами, но протух и малоприоритетен. Если бы улучшились все группы, корпус просто повторял бы то, что мы хотели услышать. Группа дистракторов — проверка на опровержение: она должна упасть, и она падает.

04

A cache that cannot go stale silently

Кеш, который не может протухнуть молча

Result, embedding and hydration caches are invalidated by MAX(oplog.seq) read from the database — so a write by another process invalidates them too.

Кеши результатов, эмбеддингов и гидратации инвалидируются по MAX(oplog.seq), прочитанному из базы — поэтому запись чужого процесса сбрасывает их тоже.

What honest invalidation costs

Чего стоит честная инвалидация

Sequence validation is global: any write drops the whole search cache. That is the price of never returning a stale answer, and it is shown here rather than hidden.

Валидация по seq глобальная: любая запись сбрасывает весь кеш поиска. Это цена того, что устаревший ответ невозможен, и она показана, а не спрятана.

05

Memory survives compaction, and knows whose it is

Память переживает сжатие и знает, чья она

The two moments where agent memory is actually lost: the context window being squeezed, and one conversation's notes leaking into another's. Both are handled, and both say what they did.

Два момента, в которые память агента на самом деле теряется: сжатие окна контекста и утечка заметок одной беседы в другую. Оба закрыты, и оба сообщают о том, что сделали.

Before the context is squeezed

Перед тем, как контекст сожмут

myc wire installs a pre-compact hook. The session episode is written to disk first — raw, L0, acl private, secrets masked — and only then a rescue packet is printed back into the context that survives. Distillation is queued, never done on the write path: exceeding the hook's timeout costs the summary, not the record.

myc wire ставит хук pre-compact. Эпизод сессии сначала ложится на диск — сырым, L0, acl private, с замаскированными секретами, — и только потом в выживающий контекст печатается спасательный пакет. Дистилляция уходит в очередь, а не делается на пути записи: превышение таймаута хука стоит выжимки, но не записи.

$ myc absorb-session --reason manual --transcript … --agent claude
# myc: context is being compacted — here is what must not be lost
episode sess-5jh8je4g050m saved (265 B)
NEXT     myc show sess-5jh8je4g050m · myc ready --claim

Whose note is this

Чья это заметка

Every note carries a reach: session for this conversation, project for everyone. The automatic context packet — prime — carries only the current session's notes, so another agent's conversation does not leak into yours. An explicit recall still finds them: hiding knowledge is not the same as scoping it. Each row says which it is.

У каждой заметки есть охват: session — эта беседа, project — все. Автоматический пакет контекста prime несёт только заметки текущей сессии, поэтому чужая беседа не протекает в вашу. Явный recall их всё равно найдёт: спрятать знание — не то же самое, что ограничить его охват. И каждая строка говорит, что она такое.

# session s1                     # session s2
ses  session note: retries…      ses* session note: retries…
prj  project note: jitter…       prj  project note: jitter…

ses own session · ses* someone else's · prj project-wide

ses своя сессия · ses* чужая · prj общее для проекта

A status line with what the agent cannot see

Строка статуса — то, чего агент не видит

myc wire --status-line puts one line under Claude Code's prompt: how full the context is, the task queue, the code index, the project's memory, and how many of this session's calls to myc returned something — counted from the host's own transcript, where an error, a refusal or an empty answer is a call but not a useful one. Opt-in; a status line that was there before keeps receiving the same input and is never waited on or killed.

myc wire --status-line ставит под приглашением Claude Code одну строку: заполненность контекста, очередь задач, индекс кода, память проекта и сколько обращений к myc в этой сессии дали результат — по транскрипту самого хоста, где ошибка, отказ и пустой ответ — обращение, но не полезное. Только по флагу; строка статуса, стоявшая до неё, получает тот же ввод, её не ждут и не убивают.

myc │ ctx 42% │ 61 ready · 34 blocked │ 612 files · 4268 symbols · 1h ago │ 101 notes │ 600/653 useful calls

Heavy commands take turns

Тяжёлые команды — по очереди

Several agents on one machine run the full test suite and builds at once and slow each other down. myc run -- <command> puts the command into one queue shared by every repository of the machine, waits for a free slot and runs it with its own terminal and exit code; myc queue shows who is running and who is waiting. A waiting command says whom it waits for, and a holder that dies frees its slot. Agents don't have to remember any of it: myc wire --queue-hook adds a Claude Code hook that sends a full test run or a build through the queue by itself and lets everything else through untouched — a command that is not heavy never starts bun or node. Opt-in. And myc run is not a way around permissions: a queued command goes through without a question only when your own rules would let the original command through; otherwise Claude Code asks and shows the whole command, and wire allows myc's subcommands one by one instead of all of them.

Несколько агентов на одной машине одновременно гоняют полный прогон тестов и сборки и мешают друг другу. myc run -- <команда> ставит команду в общую для всех репозиториев машины очередь, ждёт свободный слот и выполняет её с её же терминалом и кодом выхода; myc queue показывает, кто выполняется и кто ждёт. Ждущая команда говорит, кого ждёт, а упавший держатель освобождает слот. Помнить об этом агенту не нужно: myc wire --queue-hook ставит Claude Code хук, который сам отправляет полный прогон тестов или сборку через очередь, а всё остальное пропускает нетронутым — лёгкая команда не запускает ни bun, ни node. Только по флагу. И обходом прав myc run не служит: команда в очереди проходит без вопроса, только если ваши правила пропустили бы исходную; иначе Claude Code спрашивает и показывает всю команду, а wire разрешает подкоманды myc по одной, а не все сразу.

myc run -- bun test
myc queue
myc wire --queue-hook

08

What myc is not

Чего в myc нет

Today myc is a single-user local tool over files in git. The list below is not a roadmap teaser — it is what does not exist, stated as plainly as what does.

Сегодня myc — однопользовательский локальный инструмент над файлами в git. Список ниже не анонс: это то, чего нет, сказанное так же прямо, как и то, что есть.

Does not exist

Не существует

  • No server. myc serve is designed and not written.
  • Нет сервера. myc serve спроектирован и не написан.
  • No team mode and no ACL enforcement across users.
  • Нет командного режима и нет проверки ACL между пользователями.
  • No network sync. Machines exchange the oplog through git, and that is the only route.
  • Нет сетевой синхронизации. Машины обмениваются оплогом через git, и это единственный путь.
  • No Postgres, no containers, no hosted anything.
  • Нет Postgres, нет контейнеров, нет ничего размещённого.
  • No LLM pass over the code: no concept map, no per-symbol prose. The index is mechanical — definitions, references, spans. M3 stands at 5 of 10.
  • Нет прохода модели по коду: ни концептуальной карты, ни выжимок по символам. Индекс механический — определения, ссылки, спаны. M3 стоит на 5 из 10.
  • No routing by cost and outcome, no distillation: M5 and M6 have not started.
  • Нет роутинга по цене и результату, нет дистилляции: M5 и M6 не начаты.

Does exist, and is measured above

Существует и измерено выше

  • A task queue with leases, blockers and a parent hierarchy.
  • Очередь задач с арендой, блокерами и иерархией parent.
  • An oplog of facts and decisions, merged per field in plain git.
  • Оплог фактов и решений, сливаемый пополево обычным git.
  • Hybrid lexical + vector search with a measured MRR@10.
  • Гибридный лексический + векторный поиск с измеренным MRR@10.
  • Latency budgets enforced in CI on 100 000 nodes.
  • Бюджеты латентности, проверяемые в CI на 100 000 узлов.
  • Import from beads, with every anomaly named rather than swallowed.
  • Импорт из beads, где каждая аномалия называется, а не проглатывается.
  • A read-write web interface for boards, cards and threads.
  • Веб-интерфейс с записью: доски, карточки, нити обсуждения.
  • Loud degradation: no silent fallbacks anywhere on the hot path.
  • Громкая деградация: молчаливых откатов на горячем пути нет.
